# v0.1.0-alpha.2 — release notes (glass cards G1–G4, M2.1)

Released at commit `c9ecc2f` (G4). Evidence at release time: the CI workflow
run for this exact commit green; the native laptop workflow passes on this
exact commit (see [native-workflow.md](../native-workflow.md)); the full local
gate battery green (Rust engine + app tests, frontend build/unit, browser e2e,
style/tokens, catalogue, parity, source size).

## What's new since v0.1.0-alpha.1

### Glass cards UI overhaul, part 1 (plan v4 G1–G4)

- **Shape tokens & card primitives (G1):** the glass design language lands as
  tokens first — surface/radius/shadow tokens with a `check:token-freeze`
  gate (134 frozen colour tokens) so styles can only consume tokens.
- **MDI teardown (G2):** floating, overlapping panels are gone. Panels dock
  into stationary glass cards with a single visible tab body; PANEL_OPEN /
  TOGGLE events focus a tab instead of spawning a window. Zero
  overlapping popups for panel surfaces; docked panels stop their work when
  hidden (only the active tab stays mounted).
- **Persistent workspace shell (G3):** a two-row NLE skeleton — dock left |
  program monitor | dock right, then toolbox | timeline | master meter —
  mounted once and never unmounted when the mode switches. Edit, Color, and
  Effects route through it; dock tabs swap per mode. A geometry-invariance
  e2e walks edit→color→effects→edit and asserts the monitor, toolbox, and
  timeline never move or remount.
- **Compact timeline strip (G4):** 44px track headers (34px clip rows), the
  VOL/PAN faders leave the track headers (Inspector and Fairlight keep
  them), a 52px single-column toolbox with group separator rules, a 40px
  timeline toolbar in six named groups (Track tools / Insert / History /
  Clip / Marks / View), and a persistent 92px master meter driven by the
  audio clock master with an EBU-style gradient.

### Engine and reliability (M2.1)

- Reliable baseline restored: the Python engine harness and browser smoke
  tests are green in CI, and a native laptop workflow test proves
  create → import → edit → save/reopen → render → ffprobe on the
  real engine and GStreamer renderer.
- Honest missing-media handling: relinking is validated against the disk,
  missing-media scanning is a shipped, tested engine command, and the UI no
  longer marks title graphics as missing media.
- Honest import status: files that cannot be read, decoded, or played are
  reported by name and reason instead of being silently skipped or imported
  as wordless unknowns.
- Crash recovery contract is regression-tested: autosave snapshots restore
  edits into a fresh engine and the recovered work survives save/reopen.
- Interchange internals (EDL, FCPXML, Premiere XML, OTIO) split out and kept
  under review-size limits; no format behaviour change.

- The scripted native workflow passes: new project, ffprobe-probed import,
  timeline add + split through the real engine, save/reopen persistence

- Local gates green at release time: Rust engine + app tests, frontend
  build/unit, browser e2e contract against a mocked backend (including the
  geometry-invariance walk), style/tokens, catalogue, parity, and
  source-size checks.

## Package limitations (say this out loud)

- Packages are **known-buildable**, not known-installed: no install +
  launch result is recorded yet for any .deb/.rpm on any machine. Do not
  assume the package works before you record otherwise.
- Software H.264 is the only verified encoder path; hardware encoding is
  disabled-by-default and uncertified.
- Single laptop, single desktop environment development. Reports from other
  systems are feedback, not verified facts.
- Browser e2e tests mock the backend; they are UI-contract evidence, not
  engine or codec proof.

## Known gaps

- A large share of catalogue commands still report planned; the Fusion node
  graph actions and clip-gain/DSP edits intentionally return typed errors.
- Audio plugin slots are metadata-only until a tested native host exists;
  no VST3 hosting.
- Multicam and speech tools are placeholder surfaces.
- Project-file compatibility beyond this release's schema is best-effort;
  migrations run automatically and are fixture-tested up to the recorded
  versions.

## How to report

Attach: app version, install method, the app's diagnostics (Help →
Copy System Diagnostics), the affected area, the media codec involved, and
reproduction steps. See the bug-report template; triage details live in
[alpha-triage.md](../alpha-triage.md).
